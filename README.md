# astrbot_plugin_script_notify

把**本地脚本**想说的话，直接发到指定 QQ 会话的 AstrBot 插件。

它的定位是一个「桥」：本地脚本负责判断和生成内容，插件负责把内容推给机器人。
整条链路只读文件、调平台接口，**不经过大模型，零 token 消耗**。

## 为什么需要它

用 AstrBot 自带的定时任务做巡检播报，每次都会唤醒大模型，一天下来光「叫醒」就要烧掉不少额度。
如果只是想把「网络断了」「任务跑完了」这类固定格式的消息推给自己，
完全没必要走模型。让脚本把结果写进一个文件，插件读出来发掉，成本是零。

## 工作原理

1. 本地脚本把要发送的内容按行写进 `queue_path` 指向的文件。
2. 插件每隔 `poll_interval` 秒读一次，读到内容先清空文件，再逐条发到 `target_session`。
3. 建议脚本只在**状态发生变化**时写队列，避免刷屏。

## 配置

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `queue_path` | 播报队列文件路径 | `~/logs/notify_queue.txt` |
| `target_session` | 目标会话，格式 `平台:消息类型:会话ID` | 空 |
| `poll_interval` | 轮询间隔（秒），最小 5 | `20` |

`target_session` 怎么填：随便给机器人发条消息，然后在 AstrBot 日志里找
`unified_msg_origin`，或直接看会话列表，形如 `aiocqhttp:FriendMessage:1234567890`。

## 安装

把本目录放到 AstrBot 的 `data/plugins/` 下，然后在面板里重载插件即可。

## 示例

`examples/netwatch.sh` 是一个网络巡检脚本片段，演示了「状态变化才写队列」的写法。
把它挂到 crontab 里即可：

```
*/5 * * * * /home/you/bin/netwatch.sh
```

## 注意

- 队列文件按「先清空后发送」处理，发送失败的内容不会重试，如需可靠投递请自行加确认机制。
- 平台侧若断开连接，消息会发送失败并记录日志，不会阻塞后续内容。
