# astrbot_plugin_script_notify

本地脚本到聊天会话的消息推送桥。脚本负责判断和生成内容，插件负责把内容投递到指定会话。

## 背景

用 AstrBot 的定时任务做周期性播报时，每次触发都会完整走一遍 Agent 流程。对于格式固定、
内容可由本地脚本直接算出的通知（网络告警、任务完成、状态汇报等），这类开销并不必要。

本插件把「判断」「投递」两件事拆开：判断交给本地脚本，投递交给插件。整条链路只涉及文件读取
与平台接口调用，不经过大模型。

## 工作原理

1. 本地脚本将待发送内容按行追加到队列文件。
2. 插件按固定间隔轮询该文件。读到时先清空文件，再逐条投递到目标会话。
3. 脚本侧建议仅在状态发生变化时写入，避免重复播报。

事件顺序由脚本控制，插件不做去重与重试。

## 安装

将本插件目录放入 AstrBot 的 `data/plugins/` 目录，然后在管理面板中重载插件。

## 配置

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `queue_path` | string | `~/logs/notify_queue.txt` | 队列文件路径 |
| `target_session` | string | 空 | 目标会话，格式 `平台:消息类型:会话ID` |
| `poll_interval` | int | `20` | 轮询间隔（秒），最小 5 |

`target_session` 的取值可从 AstrBot 日志中的 `unified_msg_origin` 获得，
形如 `aiocqhttp:FriendMessage:1234567890`。

## 使用示例

`examples/netwatch.sh` 演示了脚本侧的典型写法：采集若干指标，将本次结果与上次结果比较，
仅在状态发生变化时写入队列。

挂载到计划任务：

```
*/5 * * * * /home/you/bin/netwatch.sh
```

## 注意事项

- 队列采用「先清空后投递」策略，投递失败的内容不会重试。如需可靠投递，请在脚本侧增加确认机制。
- 平台连接断开时投递会失败并记录日志，不会阻塞后续内容。
- 插件不校验内容来源，队列文件的读写权限应当收紧。

## 兼容性

支持 AstrBot v4.x，已验证平台为 aiocqhttp。其他平台未测试。
